# 交互、状态与纠错

规则依据：[requirements.md](requirements.md)。持久化与同步依据：[data-and-sync.md](../architecture/data-and-sync.md)。

## 现场主流程

1. 打开全屏球馆，查看当前轮次及三块场地；顶部同步图标反馈连接／保存状态，失败时显示提示。最后成功更新时间放在更多面板中。
2. 点球场拉近同一个三场地主场景；双指缩放，放大后拖动空地平移，点“全景”复位。三片球场、候场区和人物的世界位置不因选择场地而改变。查看本身不占用人员。
3. 点人物模型或姓名牌，再点亮起的场内位置；也可把人物拖到位置，或先点位置再点人物。发送带稳定身份和选取版本的安排命令；服务端确认保存后，人物进入预备位置。
4. 准备中可以点选后点其他合法场内位置，或直接拖到其他场地；源和目的在一次保存中更新。点本队候场标记／“回候场”或拖回本队候场区可下场。替换已有位置需核对新旧姓名并确认，失败保留原阵容。
5. 阵容完整后，仅指定管理者的场内记分牌显示“确认上场”。核对双方完整姓名，“确认上场并开始”触发再次校验并保存确认阵容；之后锁住该场选手。
6. 访客点比赛中记分牌的“录入赛果”，在本机打开比分草稿；镜头拉近同一块场内记分牌，只键入双方最终比分。打开、关闭或刷新不改变共享比赛阶段。
7. 输入双方最终比分并点“确认比分并结束比赛”。服务端校验、计算获胜方、一并保存赛果与结束时刻，场次变为比赛结束，选手继续留在原场内。
8. 当前轮所有正式比赛录分后显示“等待本轮确认”；选手继续留场，仅指定管理者可确认本轮结束并进入下一轮。新轮草稿为空，所有选手回候场，其他设备同步到新当前轮。
9. 通过轮次控件查看历史，再点对应球场／记分牌看确认阵容、比分和更正记录。

步骤 6 只是本机录分编辑，步骤 7 才确认结束。比分输入草稿保存在当前设备，只有正式提交才成为共享赛果。所有访客含匿名均可查看、准备排阵及首次录分，开赛、轮次确认和纠错保留管理权限。

## 场景与手机布局

- 球馆占满动态视口。竖屏纵向排列三块场地，桌面横向排列；放大、平移时始终保留同一个世界，镜头选择不筛掉其他场地或把人物重新放回候场区。赛程、赛果和管理项按需打开。
- 正交镜头支持单指旋转、双指缩放平移及全景复位；人物拖拽与镜头手势分开，双指手势取消人物拖拽。相机只表达本机查看，不改变业务记录。
- 候场角色按队伍分组和稳定顺序排列。选中人物时亮起合法场内位置；先点位置时区分队伍／性别不符的角色。锁定状态可查看原因。
- 人物与姓名牌共用选中语义，姓名牌不是姓名输入表单。
- 黑白队用服装、轮廓及文字区分；人物身份还由姓名、稳定编号和外观差异共同表达。
- 普通按钮与人物热区以 44–48 CSS px 为初始目标，热区避免重叠。
- 使用数字键盘；输入字体至少 16px；兼顾 safe area、动态视口和键盘遮挡。
- 记分牌根据阶段和权限显示操作与有效比分。录分在牌面展开，固定 matchId、阵容／赛果版本与 generation，显示轮次、场号、类型和双方姓名；协作参与者可首次录分，只有管理者可更正。
- 录分不建立遮罩或替换场景；输入期间锁住镜头和其他场内操作，关闭后回到原镜头，草稿保留。根据 visualViewport 调整牌面位置，短屏牌内滚动，确认按钮保留在底部；实际 iPhone 键盘仍需实机验证。
- 未获写权限者仍可探索球馆和历史，但不显示可执行的修改控件。
- 请求未确认时显示待保存，不以入场／庆祝动画冒充成功；动画中断不影响数据。
- 拖拽只产生本机半透明预览。松手后重新校验 matchId／slotId／playerId 及 revision／generation；本队候场区触发移出，其他无效区域或取消不提交，版本变化不自动改派。
- 第一轮开放前、未来轮次和未进入名单更正的历史场次，人物只供查看。拖拽不能绕过明确开赛或原有占用约束。

## 四层状态

| 层级 | 状态 | 转换条件 |
| --- | --- | --- |
| 活动 | PREPARED / WARMUP / ACTIVE / FINISHED | 人工开始热身／正式活动；所有轮次完成后人工结束 |
| 轮次 | UPCOMING / OPEN / CLOSED | 只允许一个 OPEN；全部场次完成后人工推进 |
| 场次 | PLANNING / PLAYING / COMPLETED；兼容旧 AWAITING_RESULT | 准备中／比赛中／比赛结束，只有有效录分才正常结束 |
| 选手 | available / reserved / playing / played_this_round | 根据各场草稿、确认阵容和阶段推导，不单独持久化布尔标记 |

在 PLANNING 下派生三种 UI 状态：0 人为“待安排”；部分人员或校验未通过为“选人中”；齐全且合法为“阵容待确认”。不再独立保存三个可矛盾的状态字段。

~~~mermaid
stateDiagram-v2
    state "待安排／选人中／阵容待确认" as Planning
    state "比赛中" as Playing
    state "比赛结束，选手留场" as Completed

    [*] --> Planning
    Planning --> Planning: 全员安排／跨场移动／移出／替换
    Planning --> Playing: 指定管理者确认上场
    Playing --> Planning: 实际未开打，撤销误开赛
    Playing --> Playing: 打开／关闭本机录分草稿
    Playing --> Completed: 全员确认有效最终比分
    Completed --> Playing: 管理者撤回当前轮首次误录
    Completed --> Completed: 提交更正版本
~~~

| 阶段 | 允许操作 | 保存效果及场景效果 |
| --- | --- | --- |
| PLANNING | 协作排阵／移出／跨场移动，管理者确认开赛 | 保存草稿；确认时固定阵容并锁定选手 |
| PLAYING | 查看、本机录分及确认，管理者受限撤销误开赛 | 打开草稿不改变阶段；有效比分提交才结束 |
| AWAITING_RESULT（旧版兼容） | 继续录分，管理者撤销旧结束声明 | 新界面不产生此状态；按未确认赛果展示，阵容保持锁定，允许直接提交 |
| COMPLETED | 全员查看，管理者更正／受限撤回／名单纠错 | 有有效赛果，人物仍在原场内；只有推进新轮才回候场，同轮参赛资格不释放 |

第一轮开放前，热身不产生正式参赛记录。轮次中每场独立推进，允许“1 号比赛结束、2 号比赛中、3 号准备中”。全部赛果齐备仍为 OPEN，显示等待确认；只有 AdvanceRound 关闭本轮。

activeRoundId 是业务状态；viewedRoundId 是当前设备的查看状态。查看历史不能改变 activeRoundId 或另一台手机的镜头。正在查看历史的设备收到推进通知时可以保留历史视图并提示最新当前轮。

## 占用与全轮可行性

- 草稿占位以 eventId + roundId + playerId 唯一，同一选手不占两场草稿。
- 确认上场产生有效确认阵容和本轮参赛事实。
- PLAYING 占用人员和实体场地；正式比分提交后结束，不释放本轮参赛事实。赛后留场是对阵展示，不是允许重复参赛或继续占用下一轮。
- 移出或取消草稿释放草稿占位。替换必须整体成功，否则原草稿保持原样。
- 完成后仍禁止同轮二次参赛；新轮开放时依据新 roundId 重新推导资格。
- 同轮准备中的选手可以跨场移动，命令明确携带原席位和目的席位并原子保存；不移动已确认阵容，不能借移动绕过占用或可行性校验。
- 排阵每次变更检查剩余席位是否有可行解，不必向用户推荐具体解。
- 第 6 轮每队混双和女单需两名女性，因此自由双打每侧至多使用剩余的一名女性。这是全轮可行性推导，不是为自由双打额外制定性别规则。
- 取消和移出未开赛草稿始终允许，不因暂时缺人而拒绝撤销。

## 纠错规则

### 草稿调整

只作用于 PLANNING。服务器确认后全员看到新草稿。冲突时保留当前服务器状态，提示重新查看阵容，不静默覆盖。

### 撤销误开赛

仅当前轮、PLAYING、无赛果且实际尚未开打。用户点选预设原因确认实际未开打；无法由软件自动判断真实世界是否开打。失效本次确认版本、释放在场占用和此次参赛事实，恢复原草稿占位；保留审计，不删除旧记录。

### 撤销旧版误结束（兼容）

仅管理者可将当前轮旧 AWAITING_RESULT 恢复为 PLAYING，重新验证占用、保留原开赛时间。新界面打开录分不提交结束声明，关闭草稿无需执行撤销。

### 比分更正与撤回

更正编辑时旧有效版本继续生效，新版本原子提交后替换。原因用预设选项；双方填反可以提供交换按钮。撤销一次更正也产生新的版本，不删除旧版本。

当前轮未关闭时，管理者可撤回首次误录赛果，回到 PLAYING 并阻止推进；旧结果版本保留。已经关闭的历史轮只做原子更正，不制造空结果，也不回退当前轮次。

### 实际名单录错

只允许通过“更正实际参赛者”入口操作角色，不等同允许比赛中途换人。检查该历史轮的参赛冲突，以及记录中的在场区间冲突；建立新的确认阵容版本。若已有赛果，同一次提交生成引用新阵容的赛果版本，比分保持不变；旧版本仍可追溯。有冲突则拒绝更正并指出场次。

## 轮次推进

- 本轮所有正式场次都存在有效赛果且为 COMPLETED，才可执行 AdvanceRound。
- 第 1–6 轮为 3/3，第 7 轮为 2/2；休息区域不计入。
- 仅指定管理者确认，由服务器同一次提交关闭当前轮并开放下一轮；重复点击不得跳过一轮。进入新轮重新排阵，全部选手回候场，历史轮保存的阵容不变。
- 第 7 轮全部完成后关闭该轮，并允许人工结束活动，不创建第 8 轮。
- 开放条件不检查计划时间；绝无到点自动推进。
- 历史比分更正不改变 activeRoundId；队伍总成绩未定义不会阻碍单场和轮次完成。
