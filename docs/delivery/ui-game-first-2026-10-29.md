# 全屏球馆与人物交互优化

日期：2026-10-29（Asia/Shanghai）。依据用户补充的三条界面准则，沿用原有业务规则、权限和共享存储。本轮只做本地开发与验证，没有创建、注册或发布 Site，也没有修改原始名单及赛程模板。

## 实现边界

- `app/placements.ts` 通过 `competition.decide` 产生合法目标及拒绝原因，场景不复制人数、性别、队伍、占用或全轮可行性规则。
- 拖拽保留起手时的 revision／generation，目标携带 matchId／slotId／playerId。半透明代理不写数据库；松手后重新校验，服务端确认后才移动已保存人物。
- 场外松手不提交，不自动移出或换场。其他场的预留必须先明确释放；替换已有位置先显示新旧姓名。
- 实际名单更正在本机场景预览，明确确认后才产生新版本，原有效比分在预览期间继续有效。
- `venue` 的公开入口隐藏手势、镜头、投影、几何和短动画。`Scene.tsx` 与 `InteractiveVenue.tsx` 分别承担表现和交互；DOM 姓名牌仍由页面统一管理。
- `useEventSession` 通过 React 外部存储订阅管理连接，服务端渲染不启动浏览器会话。权威数据仍来自真实 D1，IndexedDB 不替代共享记录。
- 场次详情改为阵容摘要和纠错入口，常规选人表单已移除。赛程使用业务投影的“待安排／选人中／阵容待确认”，避免部分排阵仍显示待安排。

## 本轮浏览器验证

环境：Windows 上的 in-app Chromium；视口 390×844、320×568、1440×900。没有真实 iPhone 或 Safari 会话。

独立活动为 `local-ui-design-v2`，没有替换默认 `local-sophia` 或原始模板。完成以下检查：

1. 第一轮开放前，开始按钮可见，点人物只查看资料；未来第七轮也只能查看，显示两场正式比赛和休息场，不提前占位。
2. 点尼克姓名牌安排进 1 号场；把 Vvn 从候场拖入真实位置；直接点 Kyle 三维模型选中；先点黑队女性位置再点 Sophia。错误队伍位置被拒绝并保留原阵容。
3. 核对四人实名后明确确认上场。点三维记分牌录入 0:11，保存后记分牌、进度和刷新恢复一致。
4. 在场景中将实际参赛者 Vvn 更正为大海，确认后有效比分仍为 0:11，新旧阵容和赛果版本保留。
5. 2 号场使用键盘选择大飛并安排，点“回候场”释放；再次安排后通过明确确认换成阿寬。拖大飛到场外前后均为 v13，未提交比赛变更。
6. 生产预览（8787）为 viewer，没有排阵、开赛或更正控件。开发操作端（5173）将 Vvn 加入 2 号场后，观赛端已打开的详情自动显示“阿寬 / Vvn”，无需刷新。观赛同步检查时控制台 error 为空。
7. 赛程与赛果面板在 320×568 下可滚动且无横向溢出；部分阵容正确显示“选人中”，赛果显示更正后的姓名、比分与版本入口。
8. 390×844 和 320×568 近景中，十四个姓名热区及场内位置热区中心均未被悬浮控件遮挡；姓名／位置按钮以 44 CSS px 为最小热区。短屏调整场间距，第一块场记分牌不再被顶部控件覆盖。近景移除会挡住候场人物的树木。

该演练最终停在第一轮：1 号场已完成；2 号场白队两人已预留；活动 revision=14。剩余比赛未在本轮重复演练；原有七轮二十场、并发、恢复和双编辑端证据仍见[本地验收记录](local-validation-2026-10-29.md)。

本轮观测：三场总览 87 draw calls／10,788 三角形；选人近景 68 draw calls／10,148 三角形。计数依赖当前预留人数和选择状态，不作为所有场景的最大值。仍采用 DPR 1–1.5、按需渲染、短动画和减少动态效果偏好。
