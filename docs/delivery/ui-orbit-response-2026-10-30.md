# iPhone 17 单指旋转响应优化

基线 `aa9792e`，工作区与暂存区干净。用户补充：iPhone 17；问题在单指交互过程，双指放大很顺，指的是手感而非设备性能。未提供 iOS 版本。本次保留几何、材质、DPR、业务规则及生产授权，针对相机控制路径。

## 官方参考与取舍

- [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)：固定 target 的轨道控制、单指旋转、双指缩放平移，阻尼按统一更新循环处理。
- [R3F performance pitfalls](https://r3f.docs.pmnd.rs/advanced/pitfalls)：高频相机更新绕开 setState，用帧循环和可变引用，复用 Three.js 对象。
- [R3F on-demand rendering](https://r3f.docs.pmnd.rs/advanced/scaling-performance)：保留 demand，以 invalidate 请求需要的帧。

现有 Three.js 0.186.0 附带的 OrbitControls 源码也确认了旋转角位移按 clientHeight 归一化。本次借鉴以上控制原则，保留赛事的人物／席位／第二指取消仲裁；不调整赛事状态接口。

## 可复现的原因

新增 `tests/venue/orbit-response.test.ts`，先在旧代码运行失败：纯旋转 25px 后实际相机 zoom 从 20.74468 降至 16.66120，约减小 20%，但界面逻辑 zoom 仍为 1。自动全景适配混进了旋转。

原指针起手超过 9px 才应用整个累计位移，容易出现起步跳动；松手后独立惯性循环继续改目标，而 Rig 又对世界坐标做第二次 lerp，偏离恒定半径的球面轨道。并且每个移动样本和惯性帧都经过 React 状态。

相同浏览器拖动脚本的单次样本（390×844、同一独立本地活动、同样探针）：

| 观测 | 旧路径 | 新路径 |
| --- | --- | --- |
| 实际相机 zoom | 20.74468 → 7.84871 | 20.74468 → 20.74468 |
| 最小轨道半径 | 53.42010；初始 55.39856 | 55.39856，只有浮点舍入差 |
| Venue React 提交增量 | 27 | 2，手势起止 |
| 1px 移动 | 原起手门槛内不旋转 | yaw 0.604 → 0.608，zoom 不变 |

这些是控制链路对照，不是 iPhone FPS 或实机手感通过的证明。原始值在忽略目录 `outputs/smooth/before.json` 和 `after.json`。临时计数／半径探针已从源码移除。

## 实现

- 纯旋转保持缩放、中心和半径；不随角度自动缩远。小移动立即响应，3px 仅用于取消误点击。触控旋转灵敏度按视口高度统一。
- 取消拖动后的额外惯性：手指停止，视角停止。CameraMotion 保持唯一 pose；显式近景、回正、全景才作基于时间的角度／中心／缩放过渡，每帧从球面方向重建位置。
- Rig 在 useFrame 中读取 pose；输入直接更新 CameraMotion 并 invalidate，CameraHud 同帧更新工具条，不用 React 承担相机的高频状态。空闲后停止动画帧。
- 双指缩放平移入口保留；0.35–5× 范围内不隐式把 1× 当作复位。全景明确适配三场并保留方向，回正只复位方向，品牌总览恢复初始镜头。
- 录分临时视角由控制器保存并恢复，键盘尺寸变化或 Canvas 重建不会覆盖恢复点；人物拖拽和服务端提交路径不变。
