# 程序球拍、个人配色和握持升级

范围：参考用户提供的握拍图片，为原人物替换球拍。使用代码建模，未采用已废弃的 Avatar 人体、发型或 GLB 接入实验。没有更改名单、赛程、比分、积分、权限、角色路线或服务端数据结构。

## 设计与实现

- 圆角实体拍面、带倒角的深色护边、握把、端盖、握把条纹和双面斜纹装饰；拍面有实际厚度。
- 按固定 playerId 映射 13 种个人配色；Sophia 紫色／浅金，双方其他人分别有青绿、珊瑚、蓝、莓红等。换侧／轮次／数组顺序／刷新不随机变色，历史未知身份稳定映射备用色。
- 握柄中心固定在右臂末端，手掌和拇指包住柄；拍头局部 +Y，拍面 +Z，腕部略向前、向外倾斜，并让右臂稍向前抬。沿用现有行走、待机、举手、挥拍、庆祝和飞行动作。
- paddle-model 只生成一次原始部件，按个人配色和肤色缓存合并顶点缓冲；单支拍（含手掌）一个网格、全员共享一个顶点色标准材质。没有加载器、外部模型或贴图，没有新 useFrame、逐帧重建或网络请求。
- 所有共享资源由模块缓存拥有，人物切换／卸载不触发错误释放。颜色位于独立的缓存缓冲中，某人换色不污染其他实例。
- 握持由父子变换继承；热身球的装饰性固定轨迹和业务事实不改。本次不宣称做了物理碰撞或真实球拍接触求解。

## 验证

- 23 文件、192 项自动检查通过，包含配色稳定、轮廓／厚度／窄柄、方向、几何预算、缓冲复用、颜色隔离及原有业务／存储／场景回归。
- TypeScript 通过。本次文件 ESLint 检查中发现评审页相机写法被 React immutability 规则拒绝，改为使用 R3F 帧回调的相机；本次文件静态检查通过；全量 ESLint 0 errors、4 项既有警告（records 的 3 项未用参数、short-routes-harness 的 1 项未用变量）。
- 同一个 local-short-routes-4、revision 6、13 人都在候场、相同镜头的浏览器测量：绘制调用 176 → 176，三角形 12864 → 20456。每支含手掌的网格 664 三角形；未增加球拍绘制次数。桌面测量不等于 iPhone 帧率／耗电通过。
- 本地独立评审页使用真实 Avatar 与同一球拍网格，对照握持和放大轮廓；正／侧／背面和 Sophia 配色已观察，图片留在忽略目录。
- 最终代码的双客户端真实页面＋本地 D1 回归通过：头像选人、飞行、确认开赛、录分、积分更正、21 场赛程、下一轮清空排阵、偶数轮候选和匿名管理隔离；320×568、390×600、430×932 热区和积分卡通过。45 次既有交互与读取请求，动画写入为 0。开发 HMR 曾打断前一条测试，最终在独立新活动完整重跑成功。生产构建和原 Site 发布回执完成后补记。真实 Safari 触控、长时间流畅度和握拍观感由用户发布后验收，不标成实机通过。
