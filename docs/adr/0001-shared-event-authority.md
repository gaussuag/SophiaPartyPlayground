# 共享活动以服务端记录为准

状态：本次方案的架构决策；依据用户 2026-10-28 确认的全员访问、数据同步与最后发布 Sites 要求。

采用 Sites 的服务端运行环境与 D1 保存权威活动记录，客户端仅缓存视图、未提交比分和未明命令。此前以单机 IndexedDB 为权威的建议被替代，因为每部手机各自保存无法保证其他选手看到同一场次、阵容和结果。

第一版将单活动状态、审计和命令回执放在同一快照，用活动 revision 条件更新实现原子提交。14 人、20 场的规模适合接受粗粒度冲突；这样同轮资格、跨场占用和幂等回执无需跨多表协调。将来若并发量或历史体积增长，再在 records 内更换存储实现，保持业务 Interface。

离线只允许查看旧快照和编辑本机比分草稿，不允许宣称新的排阵、开赛或赛果已经共享提交。代价是正式操作需要网络；收益是避免不同设备分别认定同一选手已上场或覆盖彼此赛果。
